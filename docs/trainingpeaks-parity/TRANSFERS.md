# Calendar entry Copy and Cut

The lead verified a disposable three-day Availability entry in the live reference: Copy/Paste creates a distinct entry, preserves the source, shifts the entire inclusive span, and retains selected available sports, reason and description. Cut/Paste moves that same copied identity and preserves those fields. The reference required a reload before displaying its moved date; the app uses verified context immediately. Private evidence remains in ignored `reference-availability-copy.json` and `reference-availability-cut.json`/`.jpg` artifacts.

The lead subsequently verified Goals and Event paste behavior using disposable reference records. Goals Copy preserves title and ordered text but clears completed flags; the original remains checked. Goals Cut retains the title, text, order and checked completion while removing the source card; reference native identity is not exposed in this view and was not measured. The app implements its move under the same native identity. Evidence: `reference-goals-copy.json`, `reference-goals-copy-source.json` and `reference-goals-cut.json`.

Event Copy creates a distinct identity and preserves name, exact type, ATP choice, description and custom goals, but resets Priority and Distance to unspecified. The app applies those observed copy-only resets. Reference Event Cut preserves the original identity, type, Priority, Distance, ATP choice and description, but loses the custom goal even after reload. The app deliberately preserves that goal during Cut to avoid reproducing destructive reference behavior. This is a documented behavioral difference, not an exact parity pass. Evidence: `reference-event-copy.json`, `reference-event-cut-fields.json` and `reference-event-cut-fresh-summary.txt`.

`POST /api/calendar/entry-transfer/event%3A123` accepts `{kind,action,operationId,date,revision,reconcileOnly?}`. `kind` is `goals|availability|event`; `action` is `copy|move`. A successful response contains `{sourceId,kind,action,operationId,workoutId,annotation|event,workout,verified:true,context?,plan?,planWarning?}`. Internal native events, storage identities and receipts are stripped; Event `event` is the validated public row. Existing authentication and ownership apply; moves share the existing direct-workout mutation queue. Generic workout copy remains guarded because it cannot safely clone annotation metadata.

Event moves and ordinary Event editing share one Annual Training Plan synchronization helper. The same saved Event identity updates existing plan races and leaves unrelated races intact. A copied unspecified-priority Event is not added as an ATP race. Replaying unchanged confirmed state does not regenerate a plan. A native-verified Event with a failed plan refresh remains truthfully verified and returns `planWarning`; replay can reattempt that independent refresh without another native event write.

The first operation reads the authoritative editable source, checks its revision, normalizes exact private fields and destination, and durably records that immutable intent in the existing encrypted, connection-scoped account store before claiming transport. Copy delegates to the canonical creation service with the same stable operation identity; move delegates to the canonical revisioned update service under the original native identity. Date arithmetic preserves inclusive span through DST and month/year edges. Provider descriptions remain human text; typed detail remains encrypted privately.

Every claimed intent permits at most one first transport. Later calls reconcile the exact retained operation and require independent readback; a retry never sends a first write merely because an inner receipt is absent. A stored claim that cannot be resolved remains explicitly unconfirmed. Reuse of an identity with a different source, destination, action or revision conflicts. Fresh source edits block initial paste, while source changes after an already-confirmed copy do not change that copy's retained intent. Later destination edits cause stale receipt reconciliation to fail rather than falsely confirming the original content.

The client reads exact public source fields when selecting Copy/Cut, creates the destination attempt once, and retains it before POST. `calendar-entry-transfer.ts` binds full readback identity, sport/reason/checklist/Event fields, dates/span, verification and validated calendar projections. `calendar-entry-clipboard.ts` supplies strict deep-clone validation for the shared clipboard slot. A denied recheck cannot establish that an earlier request failed, so it retains uncertainty even for 4xx; a first definite rejection is separately reported. Clipboard storage integration and browser acceptance are owned by the lead/frontend agent.

The provider and encrypted store remain separate systems. Revisions and app claims do not provide a distributed atomic transaction or stop an external writer between read and PUT. Credential rotation retains the existing provider-connection isolation behavior.

Twelve backend/service/preview tests and eight client tests pass for observed copy resets, independent copies, same-identity moves, goal retention, ATP synchronization and replay, DST span preservation, clean provider text, lost replies, old receipt rejection, malformed/stale/read-only inputs, preflight storage failure, immutable intent, response mismatch, denied rechecks and corrupted clipboard state. The preview uses actual production adapters. Its in-memory `preview/provider-permissions` hook verifies authoritative read-only denial; `preview/provider-failure` rejects one matching native POST/PUT before mutation, with a definite 400/403, to test retained intent without fabricated browser responses. Production exposes neither hook. These tests are not a complete parity or live-release claim.

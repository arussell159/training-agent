# Custom Strength exercise library

The custom catalog is separate from workout prescriptions. Creating an exercise through Add Exercise → Preview Changes → Save persists its title, muscle group, instructions, optional video URL and independent parameter columns, then inserts a Single Exercise with three blank prescribed sets. Selecting a saved exercise for an existing row preserves that row's matching values and set count. Editing or deleting a catalog definition does not rewrite snapshots already inserted into workouts.

The authenticated private API is `/api/strength-exercises`, with per-exercise read/update/delete/history routes. Records and revisions are scoped to the signed-in application account. Creation uses an immutable operation identity and an opaque account-bound returned exercise identity. Updates require the exact revision. The browser retains an account-scoped pending request before sending a mutation; blocked storage prevents the request. Unknown outcomes use the same request with reconciliation enabled. A changed creation receipt requires an independently loaded current outcome and explicit user resolution before a fresh revisioned edit or new creation.

Only explicit workout Save writes to the workout provider. That workout retains the exact catalog identity and a complete prescription snapshot in private storage, while native descriptions contain readable exercise instructions/sets without metadata JSON. Catalog deletion retains the already inserted prescription and its historical identity.

Owner and Muscle Group filters search the user's real custom definitions. The app does not import or fabricate the reference's 944 built-in exercises, their media or completed-set results. Linked history covers retained calendar prescriptions and explicitly marks actual set results unavailable; separate legacy title matches are not represented as exact exercise identity matches. Video validation supports safe HTTPS YouTube/Vimeo links. Browser tests verify the link and accepted syntax, not playback availability or video contents.

Reference constraints include a required 128-character title, 1000-character instructions, observed muscle choices, default Reps/Weight lb and preview/edit/delete flows. The 500-entry catalog and 12-column bounds are app resource limits, not measured TrainingPeaks limits. The observed New Strength overflow has no Export option; no placeholder export control is added.

`tools/trainingpeaks-strength-library-check.mjs` contains thirteen synthetic localhost browser groups covering defaults/validation, real preview/save, independent catalog lookup after workout discard, filters, snapshot independence, delete and explicit workout persistence, held/rejected saves, lost acknowledgement and changed-receipt recovery, malformed successful responses, blocked storage, read-only permission, stale revisions and account isolation. Saved definitions are confirmed by separate private reads; the persisted workout must retain the observed parameter kinds/units and all three blank sets. A malformed HTTP200 with a valid but incorrect Weight unit must retain recovery and cannot insert a prescription. Cleanup validates its response and makes failures visible in the exit code and result artifact.

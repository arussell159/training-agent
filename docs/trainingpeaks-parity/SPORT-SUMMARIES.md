# Observed sport summaries and physical units

The field lists below come from live TrainingPeaks draft inspection recorded in `reference-sport-variants.json`, `reference-more-sport-variants.json` and `reference-final-sport-variants.json` under ignored `artifacts/trainingpeaks-parity/`, plus the Old Strength Builder inspection. These records establish visible fields/units, not numerical or pixel certification of every state.

| Sport              | Local visible planned fields                                                                 |
| ------------------ | -------------------------------------------------------------------------------------------- |
| Bike               | Duration, Distance, Average Speed, Calories, Elevation Gain, TSS, IF, Normalized Power, Work |
| Swim / XC-Ski      | Duration, Distance, Average Pace, Calories, TSS, IF                                          |
| Walk / Rowing      | Duration, Distance, Average Pace, Calories, Elevation Gain, TSS, IF                          |
| Other / Crosstrain | Duration, Distance, Calories, TSS, IF                                                        |
| Old Strength       | Duration, Calories, TSS, IF                                                                  |
| Mtn Bike           | Duration, Distance, Average Speed, Calories, Elevation Gain, TSS, IF, Work, Average Pace     |
| Brick              | Duration, Distance, Average Speed, Average Pace, Calories, Elevation Gain, TSS, IF, Work |
| Day off            | Duration |
| Custom             | Duration, Distance, Calories, TSS, IF |

Brick, Day off and Custom use explicit validated private `model.variant` metadata (`brick`, `day-off`, `custom`) with native `model.sport: Other`. The lighter calendar projection carries `display_variant`; header, calendar cards and builder use this identity independently of the workout name. Native Intervals sport values remain supported canonical values. Explicit picker keys distinguish variants from genuine Other, and deliberate normal-sport selection clears the variant.

The verified reference Brick builder is generic: its initial wizard uses Duration / %Threshold Heart Rate / Range, with no leg-sport controls. The app therefore preserves generic structure and does not invent linked Bike/Run entities. Brick's Average Speed and Average Pace share one precise physical value through the same reciprocal helper as Mountain Bike. Normalized Power is hidden; Elevation Loss appears between IF and Work in the completed column only. Its recorded row order is Power, Pace, Heart Rate. Brick Bike and Shoes are independent persisted personal fields, while any prior generic equipment remains retained. Day off has only the Duration planned row and Heart Rate extrema; a blank duration/title-only save remains truly unstructured rather than creating an interval. Existing hidden planned metrics are retained across all variant views.

Public fixed SVG path geometry/fills for these three variants were sanitized from the observed DOM capture; no markup, scripts, URLs or dynamic reference assets are embedded. Geometry extraction does not establish lossless pixel parity. `ui/tests/workout-presentation.test.mjs`, planned-value physical examples and personal-field migration tests cover the explicit identity, reciprocal values and independent equipment persistence. Enhanced browser sport checks cover 14 actual choices, including blank Day off and variant/provider readback.

Mountain Bike now exposes both Average Speed (`mph`) and the observed additional Average Pace (`min/mi`) after Work. They share one persisted physical `average_speed` value, with separate presentation identities and unique input IDs in creation, details and the builder. Valid edits synchronize the other view even when automatic duration calculation is disabled. Incomplete active typing remains intact, preserves the other view's last valid display, and must be corrected before saving. Clearing either view clears the shared value.

Draft-only source and exact-value bookkeeping preserves physical precision: a `7:00` mile is displayed as `8.6 mph` but persists `1609.344/420` metres/second rather than the rounded mph reciprocal. Conversely, a typed `17 mph` remains the authoritative physical speed even though its displayed pace rounds to `3:32`. Interval recalculation and retained-draft recovery update both presentations together. Only the canonical `average_speed` key reaches the planned-values API; draft presentation/bookkeeping fields are never saved as workout metrics.

Rowing distance and elevation are metres. Pace is displayed as `m:ss` with the observed `sec/500m` label. A 500m row at `2:00` derives 120 seconds; 3000m in 12 minutes derives the same `2:00` split. The underlying average speed is metres/second (`500/120` in the first case). Header distance labels also use metres, including structured, estimated and recorded distances.

Swim keeps the existing persisted planned-value contract: `distance_meters` historically contains **yards** for planned swims and `average_speed` contains **yards/second**. Recorded swim values remain SI. The label now matches the observed `yds` and `sec/100y` wording, while pace entry remains `m:ss`. No historical data migration or reinterpretation was performed. Explicit new-draft sport changes transfer physical quantities across that yard/SI boundary through `plannedValueDraft(values, targetSport, sourceSport)`; ordinary loads use the unchanged two-argument behavior. For example 1000 planned swim yards become 914.4m when deliberately changing to Rowing.

Live inspection of a new Swim draft, its builder, and a completed Garmin pool swim found the summary **Pools** selector disabled with `Default` selected. Its native options were `Default` (empty value), `25 Yards Pool` (`DEFAULT-25Y`), `25 Meters Pool` (`DEFAULT-25M`) and `50 Meters Pool` (`DEFAULT-50M`). The shared local summary now mirrors that disabled control. New Swim Shoes equipment is disabled; existing equipment editing remains available. The builder wizard exposed distance/intensity units but no separate active pool setting. These equipment presets therefore do not change the native workout's `poolLength`; no unsupported pool-save workflow is claimed.

The native pool length is independently preserved in editor documents, provider `pool_length` options and FIT exports. Import previously changed every stored metric pool suffix to yards; it now retains a legitimate `25m` or `50m` pool while keeping the existing yard step/pace convention intact. Missing legacy pool length still defaults to `25y`. Zero, malformed and nonfinite pool lengths are rejected before a provider write. `app-backend/lib/workout-pool-length.test.mjs` checks create, durable metadata restart, pool change, reload, unchanged 1000-yard steps / 914.4 physical metres, and clean outgoing provider descriptions. The browser sport check covers the disabled equipment control across creation, builder and reload. Pixel geometry remains subject to paired lossless reference capture.

Drafts retain all canonical planned metrics even when the current sport hides a field. Saves send genuinely changed fields only; hiding a field does not clear existing provider/application values. Sports without a visible pace row do not invent a hidden pace through automatic calculation. Display rounding remains separately subject to comparison with populated reference data; the empty-form field inventory alone does not establish exact rounding parity.

Recorded Min/Avg/Max rows are also sport-specific: Run displays Pace and Heart Rate; Bike and Mountain Bike display Heart Rate and Power in the observed order. Swim, Rowing, XC-Ski, Walk, Crosstrain, Other and Old Strength display only Heart Rate. The same selector is used by creation, details and builder summaries. Imported workouts use the canonical editor/provider sport before a broad display alias, so a native Mountain Bike event cannot silently fall back to ordinary Bike rows when reopened.

`ui/tests/planned-workout-values.test.mjs` checks independent physical examples, legacy swim storage, explicit sport conversion, invalid clocks, hidden-value preservation and recorded/structured Rowing labels. `tools/trainingpeaks-sports-check.mjs` additionally checks real browser creation, invalid Rowing pace without a provider write, native 500m/120s readback, and reload consistency on a disposable synthetic provider. Local tests do not establish unexamined TrainingPeaks calculation or visual parity.

The focused `APP_TEST_SPORT=MountainBikeRide` browser run also passed creation and reciprocal editing with automatic calculation disabled, incomplete pace rejection before a provider mutation, exact seven-minute split persistence despite the rounded `8.6 mph` display, unique DOM identities, reload consistency, and subsequent saved edits through both mph and pace views. The verified edits retained one native mile distance target while changing its planned duration to four and then three minutes. Evidence remains in ignored `artifacts/trainingpeaks-sports/MountainBikeRide/`; these are synthetic workflow checks, not a pixel-parity score.

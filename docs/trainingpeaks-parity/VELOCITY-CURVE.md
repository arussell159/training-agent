# Native speed and pace by sustained duration

The new authenticated read-only `/api/performance-curves?kind=velocity&sport=all&start=YYYY-MM-DD&end=YYYY-MM-DD` supplies physical velocity by duration for Peak Speed and Peak Pace. It is separate from the existing Run/Swim **distance** pace curves, which retain their original source/axis/behavior. No Home, personal-statistics, HR, cadence or distance-pace read gains a velocity request. Native type/family selection, strict valid bounded dates, duplicate/unknown query rejection and explicit unsupported tag filtering follow the dedicated cadence pattern. Native all means the eligible recognized types in the recording inventory, with no upstream All token or Run/Ride substitution.

The [current official schema](https://intervals.icu/api/v1/docs) documents per-recording `GET /api/v1/activity/{id}/power-curves.json?types=velocity_smooth&fatigue=normal`. Its only selectors are stream types and normal/fatigued curves; no fractional precision or scale selector is documented. The provider maintainer announces [arbitrary-stream curve computation](https://forum.intervals.icu/t/intervals-icu-news-2025-03-14/93893/1), documents the [velocity stream and metric source model](https://forum.intervals.icu/t/server-side-data-model-for-scripts/25781/16), and explicitly states that [API speeds use m/s, with user-unit conversion in the web app](https://forum.intervals.icu/t/api-access-to-intervals-icu/609/631). Native `velocity_smooth` is the requested source; no app smoothing, grade adjustment, moving-time conversion or local reconstruction is applied.

Exactly three authorized GET probes used existing trusted configuration and existing Ride/Run/Swim recording identities from the prior inventory. All returned200 and one explicit normal `velocity_smooth` PowerCurve, with aligned seconds/values/identical watts alias/source-index arrays. All returned scalar samples were integers; Swim included a real zero. Returned curves had no authoritative recording identities/dates/units, so request URL plus the recording inventory binds provenance. Private responses are retained only in ignored artifacts; no identities, private measurements or credentials are copied here. Integer-only precision is observed, but rounding versus truncation is not established. The adapter preserves reported values and warns about coarse native precision; it does not claim exact TrainingPeaks numerical equivalence or invent missing decimals. Future raw-stream calculations could improve precision only after independently specifying sampling/gap/pause/ignore rules; interpolating integer curve samples would not recover that evidence.

The version1 DTO exposes `kind:velocity`, `unit:m/s`, `source:intervals-activity-velocity-curves`, `unitPolicy:native-velocity-smooth`, `valuePolicy:native-reported`, `tagsSupported:false`, exact selection/window, points, coverage and a static precision/coverage warning. Each point has exact positive native `duration_seconds`, finite nonnegative `value` or null, verified requested activity ID/native type/local date, bounded name, `estimated:false` and optional structural source-index pairs. Zero is measured speed, while pace at zero has no finite denominator and must remain unknown. Speed display conversion is ordinary physical conversion; duration pace is the reciprocal of a positive velocity in the selected distance units. These operations do not create additional source precision. The full native axis is preserved; the fifteen observed reference durations are exact lookups only. No interpolation, nominal distance conversion, per-record instantaneous maximum, universal Swim row count or distance-curve substitution occurs.

The narrow inventory includes native velocity availability, date/type/name, elapsed/moving duration, sync revision, `ignore_velocity`, `ignore_pace` and `ignore_parts`. Known whole-record velocity or pace exclusions cannot win or trigger source reads. Their count appears as `excludedIgnoredRecordings`. Other sensor ignore flags do not suppress velocity. Relevant pace ignored parts require valid source-index metadata: a sample overlapping an ignored range, touching its boundary conservatively, or lacking a valid index pair remains null. This conservative exclusion does not claim exact native endpoint boundary conventions or independent raw segment proof. Invalid ignore metadata fails closed and marks partial inventory rather than silently treating an excluded recording as eligible.

Per-source validation rejects wrong/fatigued/ambiguous streams, malformed/aligned arrays, conflicting generic aliases, inconsistent supplied provenance and invalid native axes. Known-too-short source durations or inconsistent supplied activity identity cannot provide measured values. Source provenance remains known when a returned sample is masked; wholly absent durations are absent. Maximum velocity combines only exact matching native durations, which also selects the fastest positive reciprocal pace. Optional indices do not authorize automatic analysis/effort highlighting: observed numeric actions open ordinary Summary, with date cells plain text.

Coverage reports selected valid inventory, eligible/fetched/failed/missing/skipped recordings, known no-velocity exclusions, ignored whole-record exclusions and unknown output samples. At most128 deterministic newest-date/ID candidates are fetched per request, four at a time; omitted candidates remain explicitly `skippedForCap` and partial. The inventory bound is10,000 rows; malformed/incomplete inventory, masked or missing samples and failed sources also report partial. All attempted source reads failing returns502, rather than false empty success. A truly empty eligible set returns no points. A cap-limited maximum is only among fetched eligible sources, never an assertion about unfetched recordings.

Whole-window and per-record validated caches are isolated by trusted actor/origin, provider credentials/account, athlete-local day, exact window/selection and source type/date/length/sync/ignore metadata. Pending work coalesces and caller results clone. One canceled subscriber does not cancel other readers; shared work has a60-second deadline and bounded active/cache capacities. Complete successful reads expire after30minutes; partial/missing/failure reads retry after a60-second cooldown. Manual sync and persisted provider refresh invalidate velocity caches independently. HTTP responses are private/no-store and safe errors cannot expose native payloads/keys. No provider write, schema or configuration change occurs.

The separate disposable preview adapter uses the production service/projector with physical time/velocity/distance streams and real native-shaped curves. It includes Ride/Run/Swim, measured zero, missing/wrong-stream/no-stream/ignored/short candidates, a pace ignored-part sample and a null non-grid duration. Its explicit localhost-only cap scenario supplies130 candidates through the real128 limit, with higher omitted values. Normal source Summary dependencies use real read adapters and truthful empty comments/personal/files; no fabricated highlight or native mutation occurs. Thirteen backend regressions exercise strict/native/source/ignore/precision/zero/null/cap/cache/auth/cancellation behavior, raw weighted recording oracles and actual routed HTTP reads. The registered UI resilience test uses the unchanged strict workout validator and physical analysis samples. Integrated frontend/browser verification and exact reference algorithm/pixel parity remain separate release gates.

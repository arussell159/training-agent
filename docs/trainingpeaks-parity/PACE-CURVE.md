# Additive full Run and Swim pace curves

Personal statistics adds `paceCurves:{Run:DTO|null,Swim:DTO|null}` using its existing cached native pace-curve bundles. There are no new provider queries or writes. Existing `bestEfforts`, Home anchors, power curves and their query/cache contracts remain unchanged. Each failed sport has its own optional safe `paceCurveErrors` entry; a healthy sport is retained independently. An absent source period is a successful empty points list.

Each version1 DTO contains `sport:"Run"|"Swim"`, `kind:"pace"`, `unit:"m/s"`, `source:"intervals-pace-curve"`, exact requested `{oldest,newest}`, `points` and nullable `warning`. Each point retains the exact native `distance_meters`, nullable `elapsed_seconds` and `value`, native activity identity/date/name, and `estimated:false`. Known speed is exactly native distance divided by native elapsed seconds. Zero elapsed is invalid and stays unknown, avoiding invented infinite or zero pace. Source distances such as1609m and1609.344m remain distinct. No interpolation, nominal-distance adjustment, rounded distance matching or whole-activity average fills missing points.

Axes must be strictly increasing, unique positive finite native distances with at most10,000 aligned points. Source period identity and any explicit bounds must match the requested window. Explicit grade-adjusted `GAP` curves are rejected; the existing request specifies `gap:false`. Known samples require a valid matching native identity, in-window valid date, compatible sport and no `ignore_pace:true`. A known recording duration shorter than the source elapsed, or recording distance shorter than the source distance, makes the sample unknown. Compact native metadata may omit sport or total length; absence remains unknown eligibility rather than a fabricated length. Existing source queries and cache isolation remain the authority for selected sport.

Optional source indices are retained only as aligned, nonnegative integer start/end pairs with end greater than start. Malformed per-point indices are omitted and warned about; they are not guessed from elapsed time. They do not alone prove a selectable raw-recording segment. Effort-detail loading must independently verify raw samples and segment bounds before a browser highlight or source-detail claim. Raw provider errors and unrelated activity fields are not exposed.

Observed reference Peak Pace by Distance examples include Run rows at800m,1km,1600m,1mi,5km,5mi,10km,15km,10mi and Half Marathon in one28-day window; a longer window additionally showed30km. An observed Swim window had a header with no effort rows. Those observations do not establish a universal distance list or missing-row rule. This adapter retains all native points; it does not manufacture those reference rows, source dates or numerical equivalence. Fourteen-sport/All support and reference UI integration are outside this backend slice.

Nine independent regression tests cover exact full axes and numeric provenance, null/zero elapsed semantics, ignored/mismatched/out-of-window/impossible recordings, malformed/oversized/alignment/period rejection, optional indices, unchanged legacy anchors/provider request count, account/window/cache clone isolation and independent safe failures. The synthetic preview adds separate literal Run/Swim distance/elapsed pairs, including distinct1600/1609.344m samples, a non-grid1234m unknown, and91.44/100/914.4m swim samples. Its complete curves now run through the actual production projector. Isolated exact Run and Swim recordings provide matching raw timestamps/distances, native curve sample indices and independently checked segment bounds; other existing recordings are unchanged. Separate positive native attempts from ignored and known-short sources become null through production eligibility checks. A localhost-only read-only source oracle supports browser verification, and an actual HTTP regression verifies that raw analysis and selected bounds agree. Nonisolated pace sources without exact raw sample bounds now explicitly return unavailable instead of guessed segment locations. Full backend verification passes773 tests; frontend/browser pace integration remains a separate gate.

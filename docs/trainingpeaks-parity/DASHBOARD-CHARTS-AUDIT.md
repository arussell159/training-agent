# Desktop dashboard chart instances

This checkpoint implements a bounded chart-library, layout and settings workflow. It does not certify complete TrainingPeaks functionality or a visual error percentage. Reference screenshots available for this slice are JPEG diagnostics; geometry/HTML observations are separate evidence.

## Observed and implemented

- The library contains the 27 observed chart names, search, drag-to-add and a keyboard Add action. Each added chart has a stable independent identity; duplicates retain independent settings. Drag reorder, explicit keyboard move actions, duplicate and remove persist a real layout.
- Existing eight visibility preferences migrate to instances, including Run/Bike/Swim distance filters. Overview, the app branding, header/sidebar and Workout Comparison remain available.
- Duration/TSS settings support custom title, all 14 reference sport types plus All, 25 reference date presets, custom dates, day/week and Show Average. Apply and Apply & Close await validated server persistence; Close cancels the settings draft. Invalid date ranges do not request history or write preferences. Settings focus returns to the invoking control.
- Chart date ranges resolve independently through the paginated history loader. The 730-day preset is accepted; month/year/future presets use actual inclusive calendar bounds. A superseded request cannot replace the current chart. Failures retain previous displayed data with its actual range and an explicit retry.
- Queued writes check the active connection before dispatch and before accepting readback. Auth/cache resets invalidate old client generations; an old connection’s queued change cannot dispatch under a later login. The live in-memory context supplies the connection check even when local storage is unavailable.
- Preferences use a connection-scoped `desktopDashboard:<scope>` namespace. Writes serialize per namespace across component lifetimes and submit immutable snapshots. A successful HTTP status is insufficient: the returned validated layout must equal the attempted layout. Local cache entries explicitly remain pending until server confirmation. A delayed initial server read cannot overwrite an edit. A late acknowledgement cannot overwrite a newer local cached layout.
- Real recorded measurements supply duration, distance, TSS, calories, elevation gain, kilojoules and longest-workout values. Missing source values remain unknown; known zero remains zero. Arithmetic averages use available displayed period values. Empty periods remain distinct from periods containing recordings with missing measurements.
- HR/power/speed zone groups preserve sport, historical thresholds, boundaries and zone basis. Different historical schemes remain separate. Weekly variants show the actual aggregate periods; ordinary variants show the selected range total.
- Metrics shows daily athlete snapshots, or the last recorded snapshot in each week, including explicit clears. Snapshot values are never added across days. Source units are retained and subjective labels do not become numeric scores.
- Fitness Summary uses the observed four report types (Planned/Completed Distance/Duration), custom title and date controls. It renders a real per-sport pie and exact known totals/unknown coverage, using canonical planned or completed sources and their respective dates. It is not labeled CTL/ATL/TSB.
- Performance Management expands the complete inclusive daily axis with explicit null rows for absent provider days, so lines cannot join across missing dates. It displays available athlete-wide provider CTL, ATL and TSB; it does not invent sport-specific physiology or relabel an unavailable value as zero.
- Fitness History retains the existing provider-window table/graph and source-effort navigation. Its optional controlled sport props preserve the original Home defaults. Its observed settings have title, 14 sports and the six Peak Type options, without date/period/average controls. Supported sources are fixed-duration Bike Power and recorded Run/Swim Pace by Distance. Unsupported selected combinations explicitly state the missing source; arbitrary date filters are not implied.

## Known gaps

- Peak Cadence, Heart Rate, Speed and Pace are best-effort duration curves in the reference. Per-workout maxima cannot establish those curves. These four library types, Peak Pace by Distance, Power Profile and Macronutrients show explicit unavailable-source explanations; their unverified analytical controls are absent. Custom title and layout actions remain functional. Existing fixed-window Fitness History curves remain usable.
- Peak Power now retains the full genuine recorded duration axis through the additive provider-curve DTO, with fifteen exact observed grid rows, independent comparison dates and Chart/Grid modes. Explicit unknown samples break paths; no missing values are inferred. Unsupported sport or tag filters are absent. See `PEAK-POWER-AUDIT.md`; its frozen-build nine-group browser suite passes.
- Exact settings and geometry for all 27 chart types have not been observed. Generic numeric/zone/race/metrics views are real source-backed implementations, not certified replicas of every corresponding reference view.
- Race Reports exposes actual recorded race activities when identified in the source; it does not turn a planned Event into a measured result.
- Layout writes use the existing training-preferences transport, which has no server revision/CAS contract for concurrent browser tabs. This implementation serializes its own writes but cannot certify conflict detection against another device editing the same connection simultaneously.
- No standalone full-history nutrition source, arbitrary-date best-effort curve adapter, or inferred TrainingPeaks proprietary load algorithm is introduced.

# Recorded Peak Pace by Distance checkpoint

The chart reads the additive Run/Swim pace DTO from the existing personal-statistics endpoint. It accepts only the exact native physical distance/elapsed-time contract, source type/unit, selected sport and date window, bounded strictly increasing axes, source identity/date and independently consistent speed. Full native samples are retained for the chart. Unknown elapsed/value pairs stay null and break paths; zero elapsed or speed cannot become a measured pace. No activity maximum speed, average or interpolated distance supplies a sustained effort.

Run grid mapping is limited to exact available source distances observed in the reference: 800 m, 1 km, 1600 m, 1 mi, 5 km, 5 mi, 10 km, 15 km, 10 mi, HM and 30 km. This is not claimed to be the universal reference inventory. A native 1609 m sample cannot impersonate a 1609.344 m mile. Other actual native distances remain available on the full curve. Swim grid rows retain actual source physical metre distances; Run pace uses min/mi and Swim uses the app's explicit min/100 yd convention. The observed empty Swim reference window does not establish positive Swim grid labels or numerical unit equivalence. Grids over 50 rows are paginated without truncating source data.

The default chart is Run. Fourteen sports and All remain actual persisted settings; currently Run-only and Swim-only sources are supported. Other or combined selections have an explicit unavailable state rather than silently ignoring unsupported filters or combining unlike pace units. The observed 25 date presets, custom dates, independent comparison window and Chart/Grid modes reuse the existing verified dashboard layout transport, with a separate per-instance `pace` configuration. Custom titles remain untouched; default single-sport titles match the observed `Peak Pace by Distance: Run`/`Swim` shape. Date cells display source dates and link to the actual source workout with its physical effort selection.

Primary and comparison reads form one displayed snapshot. Failed or wrong-window/malformed successful responses retain the last valid pair and its actual sport/ranges, with an explicit retry. Sport/range changes cancel old consumers and cannot publish their late result; shared readers remain independent. Per-sport provider errors do not invalidate a different healthy sport. Future-only windows perform no source request; partially future coverage is explicit. No request creates or edits calendar/workout/provider data.

Raw curve indices alone never establish a selected segment. Source-detail loading must still independently validate the recording. The current synthetic pace fixture has no verified raw effort-bound samples, so navigation must not be described as verified segment binding.

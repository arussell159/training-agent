# Calendar entry clipboard

Goals and Event menus expose Edit, Cut, Copy and Delete in the observed order. Availability retains Copy and Cut. The existing day menu pastes the selected entry. They share the account-scoped clipboard slot with ordinary workout/day/week actions. Goals deletion uses the existing revisioned annotation service and confirmation dialog; durable recovery must be stored before sending DELETE. Storage denial retains the usable dialog and sends no request.

Observed copy defaults are preserved: Goals retains its ordered text/title and clears completion; Event retains name, exact type, ATP choice, description and goals while clearing Priority and Distance. Availability retains its mode, sports, reason, description and inclusive span. A copy has a new provider identity. Cut moves the original identity, preserving all private fields and shifting the complete Availability span. Event Cut deliberately preserves custom goals; the observed reference lost one during Cut/Paste, which is recorded as a reference defect rather than reproduced data loss.

Selection reads the authoritative source and revision. Before the first transfer request, the clipboard stores the operation identity, fixed destination and exact expected metadata. Ambiguous recovery resumes that intent with `reconcileOnly`, including after a full reload. A definite first rejection permits a new explicit Paste operation; a rejected recheck does not erase earlier uncertainty. Provider read-only changes and stale source revisions are enforced by the service.

Corrupt or unreadable clipboard storage blocks another selection/paste. An unresolved entry paste exposes Resume and disables Clear; its identity can be removed only after authoritative confirmation or a definite first failure. Pending identities cannot be replaced by another workout or entry selection. Matching-state checks prevent a late completion from clearing a clipboard changed in another view; account changes clear the displayed selection and guard in-flight writes. Private metadata is never written into provider descriptions. Verified Event transfers apply the existing annual-plan synchronization result and surface any planning warning.

`tools/trainingpeaks-entry-transfer-check.mjs` uses real pointer menus on synthetic localhost data. Its ten check groups passed on frozen build 52920, including menu order/Edit, denied-storage delete preflight and confirmed deletion, field preservation/defaults, copy independence, Cut identity, three-day spans, held requests, real native rejection, lost-response recovery, revision conflicts and authoritative read-only refusal. There were zero page errors or failed requests; the only HTTP errors were the deliberate 400/503/409/403 cases. Evidence and the exact UI hash are preserved under `artifacts/frozen52920-entry-strength-event-verification/`. This does not establish a visual percentage or complete TrainingPeaks parity.

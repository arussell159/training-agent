# Demand-driven recorded cadence curves

`GET /api/performance-curves?kind=cadence&sport=all&start=YYYY-MM-DD&end=YYYY-MM-DD` is authenticated and read-only. Specific sports use canonical native types or up to14 unique comma-separated types, with the existing Ride/Run/Swim families. All selects every recognized native sport in the bounded recording inventory; it never substitutes Run/Ride or sends an invented upstream All token. Invalid/duplicate query fields, invalid/future dates and unsupported native types reject. A supplied tags field explicitly rejects with `CADENCE_FILTER_UNSUPPORTED`; populated reference tags have no verified provider mapping. No cadence reads are added to Home, personal statistics, Power/Pace or HR reads.

The current [official API schema](https://intervals.icu/api/v1/docs) provides per-recording `GET /api/v1/activity/{id}/power-curves.json?types=cadence&fatigue=normal`. The maintainer describes arbitrary recorded stream curves in the [March2025 release](https://forum.intervals.icu/t/intervals-icu-news-2025-03-14/93893/1) and [activity curve comparison discussion](https://forum.intervals.icu/t/compare-activity-power-curves/93705). There is no documented athlete-wide cadence endpoint or stream selector on athlete power-curves. Two explicitly authorized read-only probes of existing Ride/Run sources returned aligned PowerCurve arrays with `stream_type:cadence`, `after_kj:0`, seconds, values, an identical generic watts alias and source indices. Generic curve IDs were not activity identities, and native curve dates/activity IDs were absent. Private responses remain ignored artifacts; no private source identifiers or values are reproduced here.

The service first requests a narrow date-bounded native activity inventory with ID/type/local date/name, elapsed/moving time, stream types and source sync revision. Conflicting/invalid/out-of-window inventory cannot supply a winner. Known streams lacking cadence are excluded without a curve request; unknown stream availability permits a bounded read. No documented cadence ignore flag exists: HR/power/pace ignore flags are not applied to this unrelated sensor. Per-recording curves must identify cadence and normal fatigue, have exactly aligned strictly increasing positive safe-integer seconds, and no more than10,000 points. Conflicting aliases, wrong streams, inconsistent source dates or malformed arrays reject that source. A value must be finite/nonnegative and fit the known recording length and any supplied source identity. Decimal native RPM and measured zero remain exact; invalid/unknown samples remain null with the requested recording's verified provenance. Entirely absent durations remain absent. Optional indices are structural metadata, not independently verified production effort bounds.

The additive version1 response exposes `kind:cadence`, `unit:rpm`, `unitPolicy:native-rpm`, `source:intervals-activity-cadence-curves`, `tagsSupported:false`, exact selection/window, full points, coverage and a static warning. Every point contains duration seconds, nullable raw value, native activity ID/type/date, bounded name and `estimated:false`. Maxima combine only exactly equal native durations; no interpolation, reference-anchor fabrication, instantaneous maximum fallback or running step doubling occurs. The reference's15 observed duration anchors are a grid selection, not a guarantee that every provider recording supplies them. TrainingPeaks cadence unit/normalization equivalence across Run/Swim/cycling remains unverified. Numeric source actions open ordinary Summary; no production segment highlight is claimed.

At most128 eligible recordings per load are selected deterministically by newest local date then native ID, with four native reads at a time. A range exceeding the cap reports `skippedForCap` and `partial`; its values are maxima among fetched eligible sources, not a claim about omitted recordings. The10,000-row inventory bound, missing/failed sources, unknown samples or invalid source metadata also mark partial. Coverage counts expose selected inventory, eligible/fetched/failed/missing/skipped sources, known no-cadence exclusions and unknown output points. All source reads failing returns502 rather than a false empty success. A genuinely empty eligible range returns an empty full-axis array, without fabricated peaks.

Caches isolate trusted signed-in actor/origin and provider account, exact selection/window and athlete-local day. A separate bounded validated-source cache also binds source identity/type/date/length/sync revision so overlapping ranges can share unchanged native reads. Pending requests coalesce, callers receive clones, one canceled reader cannot cancel others, and logical concurrency/cache capacity are bounded. Shared native work has a60-second deadline. Successful complete reads expire after30minutes; failed/partial/missing reads use a60-second cooldown. Manual sync and persisted provider refresh invalidate both caches. HTTP responses are private/no-store; safe errors do not expose credentials or native response text. No schema/configuration/native write was introduced.

The synthetic localhost adapter runs this production service with independently declared native source records/curves and raw cadence/time samples. Default sources include native running decimal RPM, a zero Walk sample, Other/Strength maxima, missing and wrong-stream candidates, a known short sample, known no-cadence exclusion and sparse unknown duration. A separate explicit preview-only cap scenario supplies130 real native candidate payloads through the production128 cap, with higher omitted values to prove truthful partial coverage. Source lookup, analysis, ordinary Summary comments/personal/attachments and route dependencies are real read adapters with empty content where appropriate. Test-only scenario control is restricted to localhost preview and never exists on the production server.

Twelve backend regressions cover selection/security, actual native shape, source alignment/provenance/length, sensor-specific ignore semantics, raw weighted sample oracle, zero/null/decimal values, exact duration aggregation, genuine cap, cache/account/window/source revision isolation, clone/cooldown/cancel/capacity, authenticated routed HTTP errors and actual source Summary dependencies with zero native mutations. The registered UI resilience suite additionally passes these source records through the unchanged strict workout validator. Integrated frontend/browser gates remain separate; this slice does not certify full commercial or pixel parity.

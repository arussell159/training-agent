## Implemented workflow

The editor loads the selected date and current revision before enabling edits. An empty day opens the fourteen-field Add All panel. Values and times are staged with Add before a main Save can write; panel input and staged cards perform no provider writes. Individual fields can be added or edited, a new draft metric can be removed, and a recorded value can be explicitly cleared with Undo before saving. A note alone cannot create a new metric day. Clearing the final saved value remains saveable. Retained note-only days remain accessible from the calendar.

Numeric zero is a value, missing values and absent imported times remain null, and defaults for new entry times use the athlete timezone's current hour. Unchanged imported numeric values outside the reference's entry range are displayed and omitted from unrelated writes rather than rejected. Changed resting heart rate must be an integer because Intervals.icu's official Wellness schema uses integer/int32; decimal behavior in TrainingPeaks was not established. Exact subjective labels are never coerced into Intervals.icu's different rating scales.

Save and Save & Close await confirmed persistence. An in-flight write prevents duplicate actions and dismissal. Errors retain the visible draft. A stale revision shows an explicit reload path with a discard confirmation rather than overwriting another tab. An uncertain response retains the original immutable request and operation UUID in connection/date-scoped recovery storage, with a memory fallback when local storage is unavailable; reopening offers Recheck using that identical request. Ordinary dirty dismissal requires explicit discard. History-layout changes have their own actual Save layout action; Save & Close remains disabled until that layout is saved, while Save can commit metric data without discarding layout changes.

## API and storage contract

`GET /api/calendar/metrics?date=YYYY-MM-DD` returns a validated full fourteen-field row, revision, lock state, note and source metadata. `POST /api/calendar/metrics` sends the date, revision, operation UUID, only changed metric entries and an optional changed note. Omitted entries are preserved; null explicitly clears a recorded value and its time. Successful responses require a confirmed readback before the editor marks the save complete. Existing calendar context is refreshed from validated response context or a fresh context read.

Only Weight, Sleep Hours, Percent Fat, Resting Heart Rate and HRV bridge to native wellness fields. Weight converts displayed pounds to kilograms; hours convert to seconds. An explicitly changed note bridges to wellness comments. Subjective values, MuscleMass, deep/REM sleep and per-metric times use the encrypted connection-scoped sidecar. Hydrated context and its date index preserve metadata-only records across reloads. Provider-scale ratings keep their source identity in compact calendar summaries and existing history graphs.

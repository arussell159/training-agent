## Save semantics

For Swim/Ride/Run summaries, Save now submits the full structured/freeform model, revision, planned values, title/date/time, manual description, comment identity and personal fields together through the durable commit client. It does not perform a personal-field or description write before that transaction. Save & Close waits for app acceptance; provider synchronization is independent. A local transaction displays pending synchronization and cannot emit the old successful-provider notification. Failed persistence keeps the dialog and drafts. Draft cancellation retains the existing explicit Save/Cancel boundary.

Summary reads use the complete editor adapter and the current local revision for accepted unsynchronized edits. Generation/revision guards prevent delayed reads from overwriting a newly accepted save. Account-change tests verify that an old account's delayed acceptance cannot publish saved fields or close the new account's view.

Recurrence resolves stable app IDs to their linked numeric provider event before using the existing schedule/cancel adapter. A saved app workout without a provider link explicitly disables repeat scheduling until synchronization, rather than silently ignoring Done. Initial unsaved repeat drafts still travel in the atomic workout save; acceptance clears only the accepted draft, while failure retains it. The normal interval role menu matches Warmup/Work/Recover/Cooldown; imported Rest/Other roles remain available when selected.

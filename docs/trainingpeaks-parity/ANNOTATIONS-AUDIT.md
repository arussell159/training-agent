# Goals and Availability entry audit

This slice adds actual desktop Goals and Availability chooser entries, forms, calendar projections and CRUD. It retains AR branding, the sidebar and calendar toolbar. The lead agent owns reference inspection; JPEG artifacts inform observed behavior and do not establish a numerical pixel score.

## Observed and implemented behavior

Goals uses the observed Add Goals/Edit Goals page, a default Goals title with a 150-character entry limit, a date, ordered text rows with completion checkboxes and reorder handles, row removal and Add New Goal focus. Pointer drag uses dnd-kit. Focused grips provide a documented Space/Enter reorder mode, Up/Down movement, Escape rollback, retained focus and live position announcements. Blank rows are omitted on save; at least one nonblank row is required with visible guidance. The reference discarded a blank second row and preserved the completed first row. Clearing its sole text did not save an empty list. Both new and existing reference forms use Cancel/Save, with Delete on existing entries; Save closes after persistence. No Save & Close button is invented.

Availability uses inclusive Start/End dates, unavailable/limited selection, the exact twelve observed available-sport labels and seven reasons. Limited mode requires a selection. Selected sports remain visible as removable chips; the menu stays open after selection and closes with Escape/outside click. Description is a plain-text contenteditable field. Saved spans render narrow ribbons on each included calendar day. Their popover has working Edit/Delete/Close and opens the authoritative saved form. Explicit deletion removes all span ribbons without touching workouts.

The reference's Availability Options menu exposes Copy/Cut. That menu is not implemented in this slice and is not represented by a dummy control. Exact date-picker/menu geometry, selected-sport icon presentation, complete rich-text behavior, every pointer gesture and mobile annotation entry remain unverified or different. No complete feature/visual parity percentage is claimed.

## Persistence and failure handling

The production annotation service owns native calendar events plus encrypted private metadata. UI requests use the shared validator and exact catalog. `GET /api/calendar/annotations/:id` loads the current row before edit. POST/PUT send a normalized discriminated entry and operation UUID, with revision required for update. DELETE binds to that same native event identity and revision. Availability end dates remain inclusive in the UI/API; the native all-day event adapter converts the end to exclusive.

The client accepts a successful save only when the verified native identity and complete normalized row match the attempted content: title, goal text/order/completion, or mode/sports/reason/description. A different row or incomplete response is uncertain rather than a successful dismissal. It sends one request, protects busy dismissal/duplicate actions, retains definite errors, and offers explicit conflict reload with a dirty-discard confirmation. Failed authoritative reads keep editing/saving disabled while ordinary calendar content remains available.

Unconfirmed operations retain the exact UUID, payload and editor draft under a connection-scoped recovery key. Recheck appends only `reconcileOnly:true`; it does not invent a new operation. The native row's opaque creation UUID safely associates a pending new draft with a saved card, avoiding same-day/content matching. Private metadata errors retain the native keyed card and route to the annotation read/error path instead of a workout editor. A provider-edited row becomes read only, preventing a stale checklist from overwriting external prose. Source warnings are shown without rewriting imported native values.

Native Goals descriptions contain readable checklist prose, not serialized private editor JSON. Native availability uses the provider's actual availability and sport fields. Brick/Custom have no equivalent native sport restriction: their exact local selections persist, while the native event allows all supported sports. A concrete warning appears before and after save; no exact native equivalence is claimed.

## Verification

Nine independent client/helper tests pass, covering blank-row normalization, identity/order/completion, valid inclusive dates, available-sport semantics, one-attempt transport, GET identity checks, immutable blocked-storage recovery and creation identity lookup. Deliberately wrong server responses with matching id/date but different text/title/order/completion/mode/sport/reason/description must remain uncertain. Delete responses for another native id are rejected. The suite is included in `npm run test:ui`.

Targeted TypeScript and ESLint passed before the coordinated integrated build. `tools/trainingpeaks-annotations-check.mjs` is a localhost-only independent browser/native-record regression with nine groups covering staging/keyboard reorder/dirty close, already-applied lost-create replay from a saved card, goal reload/failed write, actual cross-tab revision conflict, inclusive availability range and twelve selections, held-save dismissal guards/native conversion, span reload/popover/unsupported native mapping warning, failed-load retry, and deletion of only its own records.

On October 20, all nine frozen-build browser groups passed with zero runtime errors; evidence is `artifacts/annotations-final-browser.log` and `artifacts/trainingpeaks-annotations/results.json`. The actual keyboard sequence displaced rows, restored their prior order with Escape and retained focus; pointer dragging also reordered real rows. AR toolbar geometry was unchanged and the entry workspace stayed within the checked desktop widths. Canceling popover Delete preserved its native record and dismissed the focus-scoped popover; the runner reopens the saved ribbon before confirming a subsequent deletion. That dismissal state is local behavior, not a claim about an unobserved reference state. This runner uses disposable synthetic provider data and aborts external requests; it does not mutate TrainingPeaks or a live provider.

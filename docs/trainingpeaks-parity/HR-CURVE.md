# Demand-driven native heart-rate curves

The authenticated read-only `/api/performance-curves` endpoint now supports `kind=heartRate`, `sport=all|<comma-separated native types>`, and exact `start`/`end` dates. It does not add HR requests to personal statistics, Power/Pace reads or Home. Unknown/duplicate query fields, invalid dates, future endpoints, duplicate/unknown sport tokens and more than14 selected native types reject before provider requests. The fourteen-selection cap is an app resource bound, not an observed TrainingPeaks limit. Canonical enum values are exported in the browser-safe `heart-rate-curve-model.mjs`, with DTO declarations beside it. Display labels/private Brick/Custom/Day off/Race semantics are not silently accepted as native types.

App `sport=all` omits the upstream type parameter, using the combined behavior independently observed in the bounded read-only probe described in `HR-CURVE-PROPOSAL.md`. It never sends `type=All`, and `curves=all` is not used as a sport selector. Specific selections request documented native sport values. Ride/Run/Swim use established native families; other selections require exact returned native identity. Unmatched subtype winners remain unknown with partial coverage rather than becoming a fabricated equivalent. Multiple supported native selections combine only maxima at exactly matching seconds; failed or unknown components remain explicitly partial. No interpolation or activity maximum HR fills a duration sample.

The version1 DTO binds `selection:{sport,nativeTypes}` and exact `window:{oldest,newest}`. It exposes `kind:"heartRate"`, `unit:"bpm"`, `source:"intervals-hr-curve"`, points, coverage and a static warning. Points contain exact native `duration_seconds`, nullable `value`, native activity identity/type/date/name and `estimated:false`; optional source index pairs are retained only when structurally valid. Measured native zero remains0, while missing, negative and nonfinite values remain null. Sparse source axes stay sparse. Values are not forced monotone because real average-HR curves can rise across longer durations.

A separate narrow recording inventory supplies actual native type, date, `icu_ignore_hr` and available recording length; compact curve metadata alone does not establish sport. Invalid/conflicting/unclassified inventory rows, mismatched identities/dates/types, ignored sources and known-too-short recordings cannot become measured winners. Inventory is bounded to10,000 returned rows; a capped/incomplete inventory or any unverified samples/failed selections makes coverage `partial`. Otherwise coverage is `native-aggregate`, explicitly warning that all reference sports/tags have not been independently audited. The response does not claim externally complete fourteen-sport or TrainingPeaks numerical parity. Source indices alone are not raw segment proof and must not be used for a production highlight without independent recording verification.

The cache is isolated by trusted signed-in actor/origin, provider configuration, exact selection/window and athlete-local day. It shares pending reads, returns independent clones, bounds retained entries and logical request concurrency, and has a failure cooldown. A caller's abort ends its wait without canceling other readers; the shared provider operation has its own60-second deadline. Native requests use existing provider GET clients only. Authentication checks precede loading, errors do not expose credentials or raw provider responses, and HTTP responses are private/no-store. Existing manual-sync and persisted-provider-refresh invalidation also clear HR caches. No storage schema, write API or configuration change was introduced.

The synthetic preview uses the same service/projection and separate exact recorded streams. Its all-sport source includes genuine Other/Run/Strength winners, plus positive native attempts that the actual projector rejects for ignored or too-short sources. Native Walk demonstrates explicit zero. A localhost-only read-only source oracle, normal source workout/analysis reads and genuine empty comments/personal fields support independent browser checks without fabricated comments/files. Existing Power/Pace source records and legacy personal-statistics outputs are preserved. Raw synthetic source bounds are independently checked in tests; a production HR effort-highlight endpoint is not implemented by this slice.

Ten focused backend regressions cover strict selection/date bounds, zero/null and nonmonotonic source values, authoritative provenance/eligibility, malformed/aligned axes and optional indices, All omission and combined selections, safe partial failures, account/window/cache isolation and cooldown, canceled shared readers/capacity, real localhost HTTP authentication/query/error handling, and independently weighted raw synthetic source segments. The actual preview HTTP regression additionally checks integrated HR JSON plus source lookup/analysis/comments/personal reads. The registered UI data-resilience suite passes new source fixtures through the actual strict workout validator. Final integrated UI/browser verification remains a separate release gate.
